⏺ That's deliberate, and it comes from two places in the test-cases skill:

  1. The skill asks for concrete test data. Step 7 says Test data should hold
     the actual values "so the tester doesn't have to invent them and the case
     is repeatable". A placeholder like <email> leaves the choice to the tester.
     Two testers then pick different values, and a value that's already taken
     (a duplicate email) can make the case fail for the wrong reason. With
     concrete data, a case can be run as written.
  2. The example is a real, reviewed file from this project, not a template.
     SKILL.md describes it as "one specific project — copy its form and level of
     detail, not its content". It shows how concrete a case should be, so it
     contains real values.

  The emails aren't real addresses. They use example.test, and .test is a domain
  name reserved for testing (RFC 6761) that never reaches a real mailbox. Each
  case also gets its own email and national_id (qa.new1, QA-NID-0001, …) so
  cases don't collide with each other.

  Where placeholders are still right: values that don't exist until the test
  runs. In the new PILOT cases I used <R_BASIC pilot> for a server-generated ID
  and <today + 3 days> for a date relative to the run date, because nobody can
  know those in advance. Everything that can be fixed, such as zone code, weight
  or altitude, is written out.

  If you'd rather the example file be a neutral template with placeholders, I
  can change it. The skill would then need another way to show how concrete
  cases should be.
